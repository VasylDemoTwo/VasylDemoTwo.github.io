Favicon rendering test: a single vector icon

This page exists to observe how a search engine picks up and renders a website icon when the document declares exactly one icon file, at a large resolution, instead of the usual ladder of small sizes.

What this page declares

The document head contains a single icon reference, <link rel="icon" type="image/svg+xml" href="/favicon.svg">, pointing at a scalable vector file rather than a bitmap, so it carries no fixed resolution at all. There is no .ico file, no apple-touch-icon and no bitmap variant. The icon URL is stable and will not change between updates of this page.

Why the setup matters

Most websites publish a whole family of icon files: a multi-frame .ico, a couple of small PNGs for browser tabs, and a larger image for mobile home screens. When several candidates are offered, it is not documented which one a search engine will store and later display next to the site name in its results. Offering exactly one file removes that ambiguity: whatever appears in the results can only have come from this single source.

What is being measured

Once this page is indexed, the icon shown next to it in search results is inspected in the browser: its intrinsic pixel dimensions, the size it is displayed at, and the pixel density of the screen. Those three numbers show whether the icon is rendered at its native resolution or stretched, and they can be compared against pages that publish the conventional set of small icon files.

Notes

This is a technical test page with no commercial purpose. It is not affiliated with any online shop, it sells nothing and it collects no data from visitors. The artwork in the icon is a simple lotus mark on a round grey background, chosen because its thin curved lines make loss of detail easy to see at small sizes.
